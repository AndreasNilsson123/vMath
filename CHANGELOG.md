# Changelog

All notable changes to vmath. Format: [Keep a Changelog](https://keepachangelog.com); versioning policy: `docs/VERSIONING.md`.
Nothing has been released yet; the baseline for the compatibility check is the tag `v0.1.0`.

## Unreleased

### Changed
- Build and artifacts (INF-6): the library is split into `vmath-core` (`core`, `mem`, `color`, `tex`), `vmath-geo` (`geo`, `pack`, `physics`), `vmath-scene` (`bulk`, `spatial`, `occlusion`, `anim`, `gl`, `util`) and `vmath-render` (`camera`, `mesh`, `gltf`, `gpucull`), each its own Gradle project, JPMS module and Maven artifact, and `vmath` is now the aggregate that depends on all four (its module `requires transitive` them, so `requires vmath` and the Maven coordinate `vmath` still give the whole library; the aggregate is the project `vmath-all`). The tests, test templates and test resources moved into the modules too (each in the lowest module that has everything it uses), and the root project has no sources any more: it merges the coverage and runs the compatibility check. No package or class moved or was renamed, and the API compatibility check passes against the `v0.1.0` jar. `vmath-simd` now requires `vmath.scene`. `@ValueType` has class retention (it was source) so the validator sees it across modules. The code generator gained `--family-templates` and `--gpu-register`. `docs/ROADMAP.md`, `docs/CODEGEN.md`, `docs/PUBLISHING.md`, `docs/API-COMPAT.md`.

### Added
- Thick lines (`@Experimental`, new package `vmath.lines`; LINE-1 to LINE-4): `LineBatch` (polylines in double precision with an origin, a style table, bounding boxes), `LineStyle` (width in pixels or world units, caps, joins, miter limit, dashes, layers), `LineGeometry` and `LineExpander` (the geometry of a segment and the reference expansion, checked against Java 2D's `BasicStroke`), `CoverageRaster`, and five strategies chosen by the capabilities of the context: `LineStrategy` and `LineRenderPlan` write the buffers, the draws and the shader text for an indirect multi-draw with the style read through the draw index, an indirect multi-draw with the style in the segment, a client multi-draw with the segments read from a texture buffer, an instanced loop, and hairlines; `LineShaderModel` runs the same arithmetic on the CPU. See `docs/LINES.md`. Later in the same release (LINE-5 to LINE-9): `LineSet` (polylines that are added, edited and removed with stable handles, free-list slots, dirty byte ranges for the upload, compaction and growth), `TrailBuffer` (histories that fade with age in steps), `LineSimplifier` (Douglas-Peucker and Visvalingam-Whyatt for any zoom), `LineClipper` (Liang-Barsky, Cyrus-Beck, frustum planes) and `LineCulling` (polyline boxes through the frustum kernels). Three demos in the samples module use it (`line-lab`: one network in six tiers; `line-styles`: widths, caps, joins, miter limits and dashes, compared with the reference; `line-stream`: a `LineSet` that is edited every frame, with trails and dirty ranges), with a shared `LineRenderer`, `LineTier` and `PanZoom2d`. The shaders of every strategy were compiled and run on an NVIDIA driver at every GLSL version from 3.30 to 4.60 and draw what the reference draws (177 cases, `:vmath-samples:lineCheck`, samples module); the cost of each strategy is measured in `docs/LINES.md`.
- Capability-driven GPU paths (`@Experimental`, `vmath.gl` and `vmath.gpucull`; CAP-1, CAP-2, ACC-1, DRAW-1, CAP-3): `GraphicsCapabilities` (OpenGL 3.3 and up from version and extensions, Vulkan from device features) and `GlslVersion`; `StrategyChooser` (best-first choice, a ceiling, `force`, and a refusal that lists what is missing); `DrawList` with `DrawSubmission` (indirect commands, client multi-draw arrays or a loop, chosen by the shape of the list); `StructArrayAccess` (an array of structs read as a storage block, uniform block, texture buffer or vertex attribute behind one `fetch_<name>` function) and `ShaderHeader.Builder.access`; `CullBackend` and `SurvivorBatcher` (compute or CPU culling with the same grouping). The decision tables in `docs/GPU.md` are generated and tested. The GLSL of the new access modes has not been compiled on the machine it was written on.
- Map tiles (`vmath-geo`, package `vmath.geo`, not `@Experimental`): `WebMercator` (spherical EPSG:3857), `TileId` (XYZ and TMS numbering, parents and children, keys and quadkeys), `TileBounds` (conservative oriented boxes, boxes and spheres of a tile in ECEF), `HorizonCuller` (conservative horizon test against the ellipsoid), `Ellipsoids` (ray against a spheroid), `TerrainRgb` (Terrarium and Mapbox terrain-RGB codecs, grid sampling and normals) and `TileSelector` (screen-space-error quadtree selection with frustum and horizon culling and a one-level balance between neighbours). Tested against brute force; measured in `docs/LARGE_WORLDS.md`.
- Demos: a demo framework in `vmath-samples` (`Demo`, the launcher with a menu and live switching, the runner with scripted runs, HUD, fly camera, instance stream, debug line renderer, statistics, markdown report, screenshots, and a smoke check that fails on a GL error, on allocation above a demo's budget or on a blank frame); `MillionInstances` became the demo `city` (new key `X` freezes the culling camera and draws its frustum); three more demos: `culling-lab` (three batch kernels and four spatial structures behind one interface, timed and checked against the scalar kernel), `interior-portals` (portal culling in a generated building with doors that open and shut), `occlusion` (software occlusion culling in a dense city with a ray check that nothing visible is removed), `dq-vs-lbs` (a twisted arm skinned by linear blending and by dual quaternions in the shaders, checked against the library's CPU reference in a compute shader), `rigid-pile` (thousands of boxes and spheres simulated with the library's broad phase, manifolds and solver) and `sdf-sculpt` (a brush that edits a distance field, ray-picked with `Sdfs.raycast` and re-meshed with `SurfaceNets`), `terrain` (256 chunks with `MeshLod` chains chosen by `LodSelector`, drawn with one `glMultiDrawElementsIndirect`, flown along a Catmull-Rom rail at constant speed with `ArcLengthTable`) `sky-sun` (a day of `SolarPosition`, `PreethamSky`, `Atmosphere`, `PhysicalCamera` and `ToneMap`, with sliders; the shader's curves are checked against the library), `cluster-lod` (a cluster hierarchy of a dense rock, the cut chosen on the CPU or by the library's cluster culling shader, which matched its CPU reference on a GPU), `gpu-culling` (the library's object culling shader over 410,000 boxes with a depth pyramid built on the GPU, identical to the CPU model) `clustered-lights` (thousands of lights assigned by `ClusterLights` and looked up with `ClusterGrid.glslLookup`, identical to a loop over every light), `globe` (the whole Earth as Web Mercator height and image tiles on the WGS-84 ellipsoid, chosen by `TileSelector`, streamed on worker threads and drawn camera-relative with a floating origin from orbit to street level; procedural tile data), `cascaded-shadows` (four cascades fitted by `Cascades.fitAll`, the casters of each culled by `Cascade.frustum()` and `CascadeCasters`, checked against rays and against the maps of every box) and `streaming-ring` (chunks streamed through `PersistentBufferRing` into a pool of `FreeListAllocator` or `SlabAllocator`, read back and compared; `GlFences` supplies the OpenGL fences); TD-34 (`CascadeCasters` costs more CPU time than the drawing it saves on cheap casters); mouse-driven `Sliders` in the demo framework; `docs/DEMOS.md` with the rules, the structure, a backlog of 25 demos in five themes and the cards; `docs/technical-debt.md` TD-29 (the occlusion test is too slow to pay for itself on cheap geometry), TD-30 (the box-box narrow phase costs 10 us per pair and allocates per body), TD-31 (`SurfaceNets` can make edges that more than two triangles share) TD-32 (the SIMD frustum kernel is slower than the scalar one and allocates on a few hundred boxes) and TD-33 (the depth pyramid of the culling shader needs a power-of-two base and normalised device depth on OpenGL); TD-01 is closed for the three shaders above. No library API changed.
- Build: `vmath-validator`, a javac annotation processor (not published) that checks the identity rules of the value types on the attributed syntax tree while `vmath` compiles: no `==`/`!=`, `synchronized`, `wait`/`notify`, `identityHashCode`, identity-based collections or weak references on a `@ValueType`, and `@ValueType` only on records. Replaces the text-based ValueTypeChecker test (AF-9, `docs/CODEGEN.md`). The generator now keeps `@ValueType` on the generated types for it.
- Geometry: signed distance fields: `Sdf`, `Sdfs` (primitives, CSG with smooth blends, translate/rotate/scale/repeat, `normal`, `project`, sphere-traced `raycast`) and `SurfaceNets` (closed, outward-wound meshes of the zero set with optional projection and normals); `SdfBench`, measured in `docs/GEOMETRY.md`. Not `@Experimental`.
- Animation: `MorphTargets` (sparse blend shapes, weighted application for positions, normals and tangents, active-target selection, bounds growth, dense, sparse and snorm16 GPU packings), `RootMotion` (delta across loops, stripping of translation and yaw), `ClipCompression` (keyframe reduction with a measured error) and `QuantizedClip` (16-bit keys, smallest-three rotations in 32 or 64 bits, sampled in place); `ClipSampler.sampleJoint`. Not `@Experimental`. Measured sizes and errors in `docs/ANIMATION.md`.
- New package `vmath.physics`: `MassProperties` (closed forms, exact mesh integral, compounds, principal axes), `RigidBody` (implicit gyroscopic step, exact quaternion update), `OdeIntegrator`, `ManifoldBuilder` (SAT, clipping, reduction, speculative margin, GJK fallback), `ContactManifold` (warm starting) and `ContactSolver` (sequential impulses, friction pyramid, split impulses, joint sweeps over many manifolds); `ConvexPolytope` gained facets and edges. `docs/PHYSICS.md`, `AnimPhysicsBench`, `AnimPhysicsAllocationTest`. Not `@Experimental`.
- Portal and sector culling for interiors: `PortalGraph` (convex sectors, portals, doors, object membership with a sector grid), `PortalCuller`, `PortalStage`, `SectorVisibility` and `PvsMatrix` for a precomputed PVS; `docs/CULLING.md`, `PortalBench`. Not `@Experimental`.
- Core: `Mat2f` and `Mat3x2f` (2D linear and affine transforms, with double twins), `Vec4i`, 2D helpers on `Vec2f` (`fromAngle`, `polarAngle`, `signedAngle`, `perpDot`, `rotateAround`, `orient`);
  `Mat4f.shear`, `orthoReversedZ`, `isOrthonormal`, `isProjection`, `invertProjection`, `decomposeWithShear`, `translationRotateShearScale`. These are not `@Experimental`: they are covered by the compatibility check from the start.
- Geometry: `BoundingVolumes` (minimum enclosing sphere, PCA box, boxes and spheres of transformed boxes) and `KDop` (6, 14, 18 and 26 directions).
- Camera: `PhysicalCamera` (exposure value, field of view, depth of field), `SolarPosition`, `Atmosphere`, `PreethamSky`.
- Utilities: `SphericalHarmonics` (two bands: projection, evaluation, irradiance, rotation), `Ibl` (GGX terms, importance sampling, split-sum table and prefiltering), `DebugLines`.
- Geometry (GEO-2): swept tests in `Intersectionf`: sphere against capsule, box, oriented box and triangle, capsule against capsule (exact), capsule against box, oriented box and triangle (conservative advancement), and box against box (exact); `segmentTriangleDistanceSquared`. Triangles are two-sided; `t` is in units of the velocities.
- Bulk (MEM-2): the `MatrixKernel` SPI also covers `transformVec4`, `transformPositions`, `transformDirections` and `normalizeQuaternions`, with Vector API versions in `vmath-simd` (2.1 to 2.7 times faster for the transforms, 1.3 for the normalisation, measured) and an overload with an explicit kernel on `Mat4fArray.premultiply`, `Vec3fArray.transformPositions`/`transformDirections`, `Vec4fArray.transform` and `QuatArray.normalizeAll` (marked `@Experimental`). `Mat4fArray.premultiply` now runs through the kernel (2.4 times faster with SIMD).
- Build (MEM-3): `@Bulk` on a method of a template record generates `<Type>Bulk` and its double twin, with an interleaved and a planar batch loop per method made from the body of the method; `Vec2f`, `Vec3f`, `Vec4f`, `Quatf`, `Mat3f`, `Mat4f` and `Mat4x3f` mark their vector, quaternion and transform operations. `docs/CODEGEN.md`.
- Core (CORE-8): `RigidTransformf` (rotation and translation, no scale) and `DualQuatf` (dual quaternions: composition, exact inverse, normalisation, linear blending, screw interpolation `sclerp`), with double twins. Animation: dual quaternion skinning, `Skinning.jointDualQuaternions`, `skinPositionsDualQuat` and `skinNormalsDualQuat`.
- Large worlds (CORE-13): `Geodetic` and `Wgs84` (geodetic, ECEF and East-North-Up conversions), `Frame` and `FrameTransformf` (transforms that know their frames), `Rebase` and `FloatingOrigin` (camera-relative float data for a whole scene), and `relativeTo(Vec3d)` on `Mat4d`, `Mat4x3d`, `Transformd` and `RigidTransformd`. `docs/LARGE_WORLDS.md`.
- Samples (DOC-5): the module `vmath-samples` (built only with `-Psamples`; it downloads LWJGL) with `MillionInstances`, a city of a million boxes drawn with OpenGL 4.5 using the library's culling, instance writer, buffer ring and indirect draw. `InstanceWriter.writeBox` and `writeVisibleBoxes` write instances scaled to their bounds. `docs/SAMPLES.md`.
- Build: IntelliJ support. Inside the IDE the project includes `vmath-samples` by itself and runs the generator after each sync (`gradle/idea.gradle.kts`, `idea-ext`); shared run configurations in `.run/`, `.editorconfig`, daemon memory in `gradle.properties`. `docs/IDE.md`.
- Occlusion (CULL-7): `DepthBuffer.beginOrthographic(viewProjection, depthRange)` for orthographic views in all three depth conventions.
- `RoadmapBench` and the measured speeds in `docs/API.md`, `docs/GEOMETRY.md`, `docs/CAMERA.md` and `docs/UTIL.md`.

### Changed
- Maven coordinates are `io.github.andreasnilsson123:vmath` (was `vmath:vmath`) and the version is `0.2.0-SNAPSHOT`; the JPMS module name is unchanged. The japicmp baseline tag is pinned in `gradle/baseline-commits.txt`.
- Build: JUnit 6.1.3, japicmp 0.26.2, JOML 1.10.9 (test oracle), JaCoCo 0.8.15, Gradle 9.8.0; versions live in `gradle/libs.versions.toml`; Dependabot proposes updates; the library and its tests compile with `-Werror`.
- `GpuCullReference.Counters` and `ClusterCullReference.Counters` have explicit public constructors.
- `ClusterHierarchy.build` is about 3.6 times faster on large meshes (14.3 s to 4.0 s for 328k triangles): no more quadratic array copying, primitive hash maps (`FastMaps`, internal).
- `normalize()` of Vec2/3/4 and Quat, and `normalizeOrZero()` of the vectors, now keep the direction of huge and subnormal vectors (before: zeros or infinities).
- `Gltf.SkinData` has `rootTransform`; `MeshSimplifier.Result` has `remap` and `attributes` (experimental APIs).
- `TransformMath.slerp` delegates to `QuatArray.slerp` (same result).
- `Ktx2.parse` refuses a header whose dimensions describe a texture that cannot be addressed (`FormatException`), `TextureLayout` refuses one whose total size exceeds a `long` (`IllegalArgumentException`), and `TextureFormat.blocksWide/blocksHigh` no longer overflow near `Integer.MAX_VALUE` (found by the new loader fuzz tests; before: negative sizes).

- `CascadeCasters` moved from `vmath.spatial` to `vmath.camera` (next to `Cascades`; `spatial` no longer imports `camera`), and the cone computation and single-cluster back-face test are in the new `vmath.geo.NormalCone` (`ConeCull` forwards to it; `mesh` uses it directly). Neither class was in a release.
- `FloatElements` (public, cannot be extended outside the package) is the base class of `Vec3fArray`, `Vec4fArray`, `QuatArray`, `Mat4fArray` and `TransformArray`: the shared methods are inherited instead of repeated. Growth no longer overflows `int` silently for absurd sizes (`OutOfMemoryError` with a message).
- `Gltf` keeps its JSON tree in `JsonObject` and `JsonArray` (package-private), so it needs no unchecked cast, and its accessor-format, JSON-access and clip-resampling helpers are the package-private classes `AccessorFormat`, `JsonAccess` and `ClipResampling`. The JDK numbers of the build are in `gradle.properties`. `BvhQuery` and `DynamicAabbTree` share their node tests (`NodeTests`), and the two SIMD providers share `SimdSupport`.
- `Hilbert.encode2` and `encode3` are table-driven (an automaton over Morton digits): 35 ns per 3D code instead of 104 ns, the same codes; the locality order of 1M points with Hilbert went from 186 ms to 97.6 ms.
- `FreeListAllocator` keeps a bitmap of its free blocks and allocation visits only those (same offsets as before; 9 times faster when most blocks are allocated, 5 to 8% slower when nearly all are free). The build is configuration-cache safe and the cache is on by default (`gradle.properties`); `Gltf`'s skin and animation conversion are the package-private `GltfSkins` and `GltfAnimations`; `NodeTests` also holds the point-to-box distance of the four spatial structures.
- Tests: `FreeListReferenceTest` (against a list model), `SmallFeatureTest` (`SmallFeature` and `Distance` stages against their formulas), `HilbertAutomatonTest`; `ShaderCompileTest` has run against glslang 16.6.0 and passed.

### Fixed
- `Quat.angle()` was 0 or very coarse for rotations under about 1e-3 radians in float (it used `acos(w)`); it is `2 atan2(|xyz|, |w|)` now.
- `BvhQuery.raycast` and `DynamicAabbTree.Query.raycast` missed a box when the ray's origin lay exactly on one of its faces and the ray's direction was zero along that axis (an axis-parallel ray running along a face): the slab test produced an empty interval. Now such a ray touches the box, as `Intersectionf.rayAabb` says. Found by seed 23 of the nightly-style sweep; `BvhTest` and `DynamicAabbTreeTest` have the case.
- `CamerafTest.frustumAgreesWithTheProjection` expected the wrong side of the near plane for reversed-Z cameras (a test bug, the frustum was right).

### Deprecated
- `vmath.gl.Std140`, for removal: use `GlslType`, `StructLayout`, `GpuWriter` or a generated `@GpuStruct` writer.
